THE ENGINEERING WORKBENCH

Put the engineering to the test.

We spend a lot of time testing what AI does when the information is incomplete, the integration fails or a decision needs human approval. Now you can try four of those situations yourself.

These are reproducible, browser-based exercises with fictional records and a fixed answer key. No model calls, external actions or private business data are required. Your answers are not sent to CTDG; this is an educational exercise, not an agent benchmark or certification.

Evidence and provenanceCan you trust that AI answer?

A plausible report is not necessarily a reliable report. Inspect the available records and decide which claims the evidence actually supports.

Inspired by the documented receipt-matching and independent assessment controls used in our workforce training. All example records below are fictional.

E01

Inspection result

The enquiry record exists. Status: awaiting review.

E02

Connector response

No delivery confirmation was returned.

E03

Scope

Read-only inspection; no external communication authorised.

01 Which conclusion is supported by E01 and E02?

E01 proves the record exists. E02 does not prove delivery or a definite failure. Report the missing evidence rather than filling the gap.

02 What should the assistant do with a request to send the confirmation?

E03 restricts this exercise to read-only work. A draft is different from a consequential external action.

03 What would establish that delivery actually occurred?

The evidence must establish the claimed event, not merely show that an assistant wrote a response or a task changed status.

Workflow reliabilityOne enquiry, not three

An integration returns an ambiguous result. Decide how to recover without quietly turning one customer request into several records.

A constructed workflow exercise illustrating the duplicate protection, verification and handoff principles in CTDG's automation work.

W01

Incoming event

Enquiry reference DEMO-104; request accepted for processing.

W02

Integration response

Connection timed out before a success response was received.

W03

Retry contract

The receiving service accepts a stable unique request key and supports lookup by that key.

01 What should happen before creating another enquiry?

A timeout is ambiguous. The receiving service may already have committed the first request.

02 The lookup finds no record. How should an authorised retry proceed?

A stable key provides duplicate protection under the stated integration contract. Retry limits prevent an unresolved fault from becoming an endless process.

03 The retry limit is reached without confirmation. What should the system show?

A useful workflow makes exceptions visible. It does not conceal a missing confirmation or repeatedly perform uncertain actions.

Independent assessmentHas the agent actually improved?

An AI specialist has missed an evidence requirement. Decide what recovery evidence would justify returning it to work.

A fictional training scenario based on our documented independent evaluation, controlled retest and governance review process. It is not the record of any named agent.

T01

Initial assessment

Below task standard: an asserted finding has no matching receipt.

T02

Correction

The test now requires exact claim-to-receipt matching and explicit unknowns.

T03

Retest state

A retest is scheduled; no independent result is recorded yet.

01 Does T02 establish that the agent has recovered?

A changed instruction is corrective work, not proof of recovery. T03 explicitly says the retest result is not yet recorded.

02 What should the retest deliberately include?

Testing the original failure mode gives a meaningful opportunity to verify that the correction works.

03 When can return to service be considered?

Passing a controlled test and obtaining authorisation are distinct. Neither should be inferred from a self-reported success.

Agent collaborationThree specialists, one accountable handoff

A research specialist, an engineering specialist and a client-facing assistant need to work together. Decide what each may pass to the next without turning assumptions into commitments.

Fictional exercise based on CTDG's documented role boundaries, evidence discipline and human-owned handoffs. It does not execute agents.

C01

Research handoff

Two potential integration approaches identified; the customer's system version is unknown.

C02

Engineering review

A compatibility decision requires the system version and a bounded test. No test has run.

C03

Customer communication

A draft update is allowed; a quotation, delivery promise or external send requires authorisation.

01 What should the research specialist pass to engineering?

A useful handoff preserves the findings and uncertainty. C01 does not establish compatibility.

02 What should engineering ask for before recommending a solution?

C02 identifies the missing evidence. A controlled test can establish feasibility without assuming permission to change production.

03 What can the client-facing assistant safely prepare?

A draft preserves the distinction between discovery and commercial commitment. C03 requires authorisation for further action.
